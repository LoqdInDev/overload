⚙ Three Operating Modes

Each of the 25 automatable modules can independently be set to one of three modes per workspace. Stored in ae_module_modes.

Manual
Default. Zero automation — full human control.
  • Rules exist but never fire automatically
  • No tick loop evaluation
  • User triggers actions explicitly
  • Safest option for sensitive modules
  • All new modules start here
Copilot
AI-assisted — everything goes through approval.
  • Rules fire automatically per triggers
  • Every action queued to approval queue
  • User reviews, edits, approves, or rejects
  • Confidence scores inform review priority
  • Auto-set when marketplace recipe installed
Autopilot
Autonomous execution — with safety rails.
  • Rules fire and execute without approval
  • Subject to confidence threshold (default 70%)
  • Risk level can override to require approval
  • Safety limits enforced (daily, hourly, budget)
  • Low-confidence actions still get queued

↻ The 60-Second Tick Loop

The heart of the engine. Every 60 seconds, ruleEngine.js evaluates all active rules across all workspaces.

Step 1
Fetch All Workspaces
Query all workspace IDs from the database. Each workspace is evaluated independently.
Step 2
Load Module Modes
For each workspace, fetch ae_module_modes to determine which modules are manual, copilot, or autopilot.
Step 3
Fetch Active Rules
Query ae_rules WHERE status = 'active' AND workspace_id = ?. Parse trigger_config and action_config from JSON.
Step 4 — Decision
Skip Manual Modules
If the rule's module is in manual mode, skip it entirely. No evaluation, no execution.
Step 5 — Decision
Evaluate Trigger
Check if the rule's trigger condition is met: schedule time match, threshold metric exceeded, or event received. If not triggered, skip.
Step 6 — Decision
Check Safety Limits
Verify: pauseAll not set, actions today < maxActionsPerDay, actions this hour < maxActionsPerHour, monthly budget not exceeded.
Step 7 — Decision
Mode Routing
Copilot: always queue. Autopilot: compute confidence, check risk level, decide execute vs. queue.
Path A — Queue
Queue for Approval
Insert into ae_approval_queue with confidence score, priority, payload. Create suggestion_ready notification.
Path B — Execute
Execute Action
Call Claude API to generate content. Log to ae_action_log. Save draft to target module's database. Create action_completed notification.
Step 8
Mark Rule Triggered
Update last_triggered timestamp and increment run_count.
Startup: The tick loop starts 30 seconds after server boot (startRuleEngine()), giving all modules time to initialize their databases.

⚡ Trigger Types

Three mechanisms determine when a rule fires.

schedule Schedule Triggers

Cron-like timing. Fires within a 2-minute window of the scheduled time.

// trigger_config shape:
{
  "frequency": "daily" | "weekly" | "biweekly" | "monthly",
  "day": "monday" | 1,  // day of week or month
  "time": "09:00"       // HH:MM format
}

Cooldowns: daily = 23h, weekly = 6d, biweekly = 13d, monthly = 27d

threshold Threshold Triggers

Fires when a metric crosses a boundary. Currently implemented for the ads module via pa_campaign_metrics.

// trigger_config shape:
{
  "metric": "roas" | "ctr" | "cpa" | "spend",
  "operator": ">" | "<" | ">=" | "<=",
  "value": 2.0,
  "window": "7d"
}

Cooldown: 24 hours between threshold fires.

event Event Triggers

Triggered externally via POST /rules/trigger-event from webhooks or other modules. Not evaluated by the tick loop.

// trigger_config shape:
{
  "event": "new_review" | "content_published" | "new_contact",
  "condition": "rating >= 4"  // optional filter
}

Cooldown: 1 hour per rule per event type.

After first run + good config 70%

Default threshold: 70%. Rules scoring below this get queued for approval even in autopilot mode. Configurable per workspace via ae_settings.confidenceThreshold.

⚠ Risk Levels

Three risk profiles modify autopilot behavior. Stored per-module in ae_module_modes.risk_level and globally in ae_settings.riskLevel.

Conservative

ALL actions require approval — autopilot effectively becomes copilot.

Best for: brand-sensitive modules, new deployments, regulated industries.

Balanced default

High-impact actions (adjust_budget, send_campaign, publish_blog) require approval on first run (run_count = 0). Proven rules execute freely.

Best for: most teams. Good safety/automation balance.

Aggressive

Only rules explicitly flagged requires_approval = 1 need approval. Everything else executes immediately.

Best for: power users with proven, well-tested rules.

Decision Logic (Autopilot Mode)

if (riskLevel === 'conservative') {
  // ALL actions queued — overrides autopilot
  queueForApproval(rule, wsId);

} else if (riskLevel === 'balanced') {
  const highImpact = ['adjust_budget', 'send_campaign', 'publish_blog'];

  if (highImpact.includes(rule.action_type) && rule.run_count === 0) {
    queueForApproval(rule, wsId);  // untested high-impact
  } else if (rule.requires_approval) {
    queueForApproval(rule, wsId);  // explicit flag
  } else {
    executeAction(rule, wsId);     // trusted rule
  }

} else if (riskLevel === 'aggressive') {
  if (rule.requires_approval) {
    queueForApproval(rule, wsId);
  } else {
    executeAction(rule, wsId);     // execute everything else
  }
}

☑ Approval Queue

The human-in-the-loop layer. All copilot actions and low-confidence autopilot actions land here.

User Actions

Approve

Mark as approved. Logs to ae_action_log with mode: 'copilot', status: 'completed'. Creates action_completed notification.

Reject

Mark as rejected with optional notes. Logs as 'cancelled'. Creates action_failed notification.

Edit & Approve

Modify the payload JSON (tweak budget, change copy, etc.), then auto-approve. Logged with review_notes: 'edited'.

Generate Content

Call Claude to produce full content from the approval's context. Caches result in payload.generated_content. Only available after approval.

Batch Operations

Approve or reject multiple items at once. Wrapped in a transaction for consistency. Each item individually logged and notified.

Queue Sort Order

Priority ranking: urgent → high → medium → low, then by created_at DESC within each priority.

▶ Action Execution

What happens when an action actually runs — either via autopilot direct execution or approved copilot.

Execution Pipeline

  1. 1 Build Prompt — buildPromptForRule(rule) creates a context-aware prompt based on action_type and action_config.
  2. 2 Call Claude API — generateTextWithClaude() with system prompt, temperature 0.7, maxTokens 2048.
  3. 3 Log Action — Insert into ae_action_log with input_data, output_data, duration_ms, status.
  4. 4 Save to Module DB — saveToModuleDatabase() routes content to the target module's table as a draft.
  5. 5 Notify — Create action_completed notification.

🔀 Cross-Module Automation Flows

The real power of the automation engine comes from modules triggering each other. Here are the key cross-module flows:

Blog → Social → Email

Content publishes blog post → content_published event fires → Social generates platform-specific posts → Email includes blog link in weekly newsletter.

CRM → Email → Content

New contact added to CRM → new_contact event fires → Email sends welcome sequence → Content generates personalized onboarding materials.

Reviews → Customer AI → Knowledge Base

Negative review received → Reviews drafts response → low rating escalates to Customer AI → support ticket created → when resolved, ticket_closed event generates KB article.

SEO → Content → Social

SEO audit finds keyword gaps → generates content briefs → Content module creates blog posts → Social promotes published content across platforms.

Ads → Budget Optimizer → Reports

ROAS drops below threshold → Ads module alerts Budget Optimizer → budget reallocated to top performers → weekly performance report captures the changes.

Webhooks → CRM → Email → Reports

External form submission webhook → CRM creates contact → Email sends welcome → Goal Tracker updates lead count → Reports includes in weekly summary.

Module Interdependency: The automation engine acts as a central message bus. Modules don't call each other directly — they emit events and the Rule Engine routes them. This means any module can trigger any other module's actions through rules, creating unlimited workflow possibilities from 20 pre-built recipes or custom user-defined rules.
